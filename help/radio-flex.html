OscarWatch treats duplex-capable Flex radios as a single satellite radio. It connects directly to the radio on the LAN using Flex’s SmartSDR TCP/IP API (not by automating the SmartSDR for Windows application). Full duplex is enabled on the radio, with separate RX and TX slices for Doppler.

What you need

  • A dual-SCU Flex for true full duplex. Current Signature Series examples: 8600 / 8600M. Supported dual-SCU 6000-series radios include 6600, 6600M, and 6700.
  • The radio on the same LAN as the PC (API discovery/control on UDP/TCP port 4992).
  • Transverters and antenna ports wired for your satellite bands (see Antenna ports by band below).

Single-SCU models (for example 8400 / 8400M, or a legacy 6400) are not suitable for full-duplex satellite work. Settings shows a warning if discovery reports such a model.

Easy setup

  1. Open Settings → Radio, enable the radio, and leave Dual radio off.
  2. Choose FlexRadio (SmartSDR).
  3. Click Refresh next to Discovered radios (UDP discovery on port 4992).
  4. Select your radio — host and port fill in automatically (or type the IP yourself).
  5. Configure Antenna ports by band if you use separate RX A/RX B or ANT/XVTR A/XVTR B paths for 2 m and 70 cm (optional; see below).
  6. Click Test SmartSDR connection to confirm the TCP API handshake and refresh the antenna port list from the radio.
  7. Track a pass — OscarWatch enables full duplex and drives RX/TX slices on the radio.

How OscarWatch maps VFOs

Satellite modefull_duplex_enabled=1 and a two-slice layout

Continuous Doppler uses slice tune … autopan=0 so the radio does not yank both panadapters onto one band every few seconds. When a satellite (or mode) is focused, OscarWatch rebinds each slice onto the correct VHF or UHF panadapter by removing and recreating slices with slice create … pan= (the API rejects slice set … pan=, and slice m cannot safely swap two occupied pans). A V/U↔U/V layout flip, or a change of satellite, forces that recreate so a stale pan cache cannot leave RX/TX on the wrong SCU. OscarWatch then tunes, then centres the VHF and UHF panadapters once each (by locked SCU band, not by which slice happened to be attached), and sends autocenter=0 so the radio does not recentre them during Doppler. Modes (USB downlink / LSB uplink on linear SSB) are applied next. OscarWatch then reads back live RX/TX slice frequencies, modes, TX roles, and pan attachments, and retunes / force-rebinds if anything landed wrong. FM CTCSS is programmed only on FM uplink modes. Keep two panadapters active on the radio (typical dual-SCU layout) so VHF and UHF can stay available together — especially when switching from V/U to U/V satellites.

OscarWatch keeps band-locked pans: VHF frequencies stay on the VHF panadapter and UHF on the UHF panadapter (important when one pan is an XVTR). Panadapter window order in SmartSDR for Windows (which pan is on top) is GUI-only — drag the title bar, maximise, or load a Global Profile. If you prefer the downlink always on the top panadapter, arrange that in SmartSDR yourself; OscarWatch cannot reorder GUI windows over the API.

Pass layouts

  • Cross-band and same-band duplex (both uplink and downlink set, e.g. ISS packet): full duplex on, two slices. Same-band does not use classic split; Doppler still separates TX and RX on the two slices.
  • Beacon / receive-only (uplink 0): full duplex off; only the downlink slice is tracked (RX antenna mapping still applies when configured).

If both panadapters stick on one band

After rapid U/V ↔ V/U satellite switching, SmartSDR can occasionally leave both panadapters on VHF or both on UHF. OscarWatch tries to detect and repair that, but if the displays stay stuck:

  1. In SmartSDR for Windows, load a Global Profile that restores your normal dual-pan layout (separate VHF and UHF pans — for example a “VU” or satellite profile you already use).
  2. Re-select the satellite in OscarWatch so pass setup runs again.

Keeping such a Global Profile handy is the fastest recovery for Flex operators. Antenna port mapping in OscarWatch is optional and separate from this pan layout recovery.

Antenna ports by band

When you switch between U/V and V/U satellites, OscarWatch retunes both slices but the radio does not automatically move auxiliary receive ports. If your UHF transverter is on RX A and VHF on RX B, you can map those in Settings so the correct port is selected when OscarWatch initialises the duplex layout.

Ports are applied whenever a satellite (or mode) is focused and CAT pass setup runs — including below the horizon when you swap birds for testing. You do not need the satellite to be above the horizon.

Under Settings → Radio → FlexRadio, the Antenna ports by band section offers four optional mappings:

  • VHF receive (2 m) and UHF receive (70 cm+) — applied to the downlink slice (rxant).
  • VHF transmit (2 m) and UHF transmit (70 cm+) — applied to the uplink slice (txant).

Choose Leave unchanged for any row you do not want OscarWatch to touch (the default for all four). Valid API port tokens include ANT1, ANT2, RX_A, RX_B, XVTA (XVTR A), XVTB (XVTR B), and legacy XVTR (shown in Settings as RX A / RX B / XVTR A / XVTR B). Offline Settings lists these common ports; Test SmartSDR connection refreshes the dropdown from the radio’s ant list so dual-XVTR hardware (for example a FLEX-6600) shows the ports that radio actually has.

RX A and RX B are receive-only auxiliary ports (typical for transverter IF inputs). Transmit paths usually use ANT1, ANT2, XVTA, or XVTB; map TX only if your station switches those by band. On dual-XVTR radios, XVTR A and RX A typically share one SCU, and XVTR B and RX B the other.

Tips

  • SmartSDR for Windows (or Maestro) is optional for panadapter display and audio. OscarWatch talks to the radio as a separate API client whether or not that GUI is open.
  • Keep a SmartSDR Global Profile with separate VHF and UHF pans. If both pans stick on one band after satellite switching, load that profile, then re-select the satellite in OscarWatch (see above).
  • If Settings → Recording reports that audio is unavailable while SmartSDR for Windows is running, configure pass recording with that app closed — some DAX virtual audio devices fail PortAudio initialisation. OscarWatch probes audio in a separate process so this does not close the main application. Other Settings tabs are safe to use during a pass.
  • This driver is not a dual-radio leg and is not Hamlib/rigctl.
  • RF isolation and transverters remain your responsibility — OscarWatch controls frequency, mode, full duplex, tone, and optional antenna ports.

If the radio is discovered but not controlled

  1. Use Test SmartSDR connection; discovery uses UDP, while control needs TCP port 4992 to the radio.
  2. Confirm the radio is enabled, Pause CAT is off, OscarWatch is not in Standby, and a satellite with an uplink and downlink is focused.
  3. At pass start, confirm the radio has full duplex on and separate RX/TX slices (visible in SmartSDR for Windows if you use it, or via status/logs). OscarWatch reports a visible radio status if either step fails.
  4. If control still fails, use Help → Open logs folder and include the current log with your report. Flex discovery, connection, full-duplex and slice setup are recorded there.

Hardware smoke checklist

  1. Discovery lists the radio; Test connection succeeds.
  2. On pass start, full duplex is on and two slices are active.
  3. RX and TX Doppler both update during a pass.
  4. FM satellites get the correct uplink CTCSS.
  5. When antenna port mapping is configured, switching U/V ↔ V/U selects the expected RX (and TX) ports on the radio.
