OscarWatch treats duplex-capable Flex radios as a single satellite radio: one SmartSDR TCP connection, full duplex enabled, separate RX and TX slices for Doppler.

What you need

  • A dual-SCU Flex (for example 6600, 6600M, or 6700) for true full duplex.
  • The radio on the same LAN as the PC (SmartSDR API on TCP port 4992).
  • Antenna / XVTR ports already set on the radio or in SmartSDR for your satellite bands.

Single-SCU models (such as a 6400) are not suitable for full-duplex satellite work. Settings shows a warning if discovery reports such a model.

Easy setup

  1. Open Settings → Radio, enable the radio, and leave Dual radio off.
  2. Choose FlexRadio (SmartSDR).
  3. Click Refresh next to Discovered radios (UDP discovery on port 4992).
  4. Select your radio — host and port fill in automatically (or type the IP yourself).
  5. Click Test SmartSDR connection to confirm the API handshake.
  6. Track a pass — OscarWatch enables full duplex and drives RX/TX slices.

Pass layouts

  • Cross-band and same-band duplex (both uplink and downlink set, e.g. ISS packet): full duplex on, two slices. Same-band does not use classic split; Doppler still separates TX and RX on the two slices.
  • Beacon / receive-only (uplink 0): full duplex off; only the downlink slice is tracked.

Tips

  • SmartSDR for Windows can stay open for panadapter and audio; OscarWatch is another API client.
  • This driver is not a dual-radio leg and is not Hamlib/rigctl.
  • RF isolation and transverters remain your responsibility — OscarWatch only controls frequency, mode, FDX, and tone.

Hardware smoke checklist

  1. Discovery lists the radio; Test connection succeeds.
  2. On pass start, full duplex is on and two slices are active.
  3. RX and TX Doppler both update during a pass.
  4. FM satellites get the correct uplink CTCSS.
