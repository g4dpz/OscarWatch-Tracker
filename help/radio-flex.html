OscarWatch treats duplex-capable Flex radios as a single satellite radio: one SmartSDR TCP connection, full duplex enabled, separate RX and TX slices for Doppler.

What you need

  • A dual-SCU Flex (for example 6600, 6600M, 6700, or 8600) for true full duplex.
  • The radio on the same LAN as the PC (SmartSDR API on TCP port 4992).
  • Transverters and antenna ports wired for your satellite bands (see Antenna ports by band below).

Single-SCU models (such as a 6400) are not suitable for full-duplex satellite work. Settings shows a warning if discovery reports such a model.

Easy setup

  1. Open Settings → Radio, enable the radio, and leave Dual radio off.
  2. Choose FlexRadio (SmartSDR).
  3. Click Refresh next to Discovered radios (UDP discovery on port 4992).
  4. Select your radio — host and port fill in automatically (or type the IP yourself).
  5. Configure Antenna ports by band if you use separate RX A/RX B or ANT/XVTR paths for 2 m and 70 cm (optional; see below).
  6. Click Test SmartSDR connection to confirm the API handshake.
  7. Track a pass — OscarWatch enables full duplex and drives RX/TX slices.

Satellite modefull_duplex_enabled=1 and a two-slice layout

Continuous Doppler uses slice tune … autopan=0 so SmartSDR does not yank both panadapters onto one band every few seconds. When a satellite (or mode) is focused, OscarWatch also centres the VHF and UHF panadapters once each (by SCU band, not by which slice happens to be attached), and sends autocenter=0 so SmartSDR does not recentre them during Doppler. Keep two panadapters open in SmartSDR (typical dual-SCU layout) so VHF and UHF can stay on screen together — especially when switching from V/U to U/V satellites.

Pass layouts

  • Cross-band and same-band duplex (both uplink and downlink set, e.g. ISS packet): full duplex on, two slices. Same-band does not use classic split; Doppler still separates TX and RX on the two slices.
  • Beacon / receive-only (uplink 0): full duplex off; only the downlink slice is tracked (RX antenna mapping still applies when configured).

Antenna ports by band

When you switch between U/V and V/U satellites, OscarWatch retunes both slices but SmartSDR does not automatically move auxiliary receive ports. If your UHF transverter is on RX A and VHF on RX B, you can map those in Settings so the correct port is selected when OscarWatch initialises the duplex layout.

Ports are applied whenever a satellite (or mode) is focused and CAT pass setup runs — including below the horizon when you swap birds for testing. You do not need the satellite to be above the horizon.

Under Settings → Radio → FlexRadio, the Antenna ports by band section offers four optional mappings:

  • VHF receive (2 m) and UHF receive (70 cm+) — applied to the downlink slice (rxant).
  • VHF transmit (2 m) and UHF transmit (70 cm+) — applied to the uplink slice (txant).

Choose Leave unchanged for any row you do not want OscarWatch to touch (the default for all four). Valid SmartSDR tokens are ANT1, ANT2, RX_A, RX_B, and XVTR (shown in Settings as RX A / RX B).

RX A and RX B are receive-only auxiliary ports — typical for transverter IF inputs. Transmit paths usually use ANT1, ANT2, or XVTR; map TX only if your station switches those by band.

Tips

  • SmartSDR for Windows can stay open for panadapter and audio; OscarWatch is another API client.
  • If Settings → Recording reports that audio is unavailable while SmartSDR is running, configure pass recording with SmartSDR closed — some DAX virtual audio devices fail PortAudio initialisation. OscarWatch probes audio in a separate process so this does not close the main application. Other Settings tabs are safe to use during a pass.
  • This driver is not a dual-radio leg and is not Hamlib/rigctl.
  • RF isolation and transverters remain your responsibility — OscarWatch controls frequency, mode, full duplex, tone, and optional antenna ports.

If the radio is discovered but not controlled

  1. Use Test SmartSDR connection; discovery uses UDP, while control needs TCP port 4992.
  2. Confirm the radio is enabled, Pause CAT is off, OscarWatch is not in Standby, and a satellite with an uplink and downlink is focused.
  3. At pass start, check SmartSDR shows full duplex and separate RX/TX slices. OscarWatch now reports a visible radio status if either step fails.
  4. If control still fails, use Help → Open logs folder and include the current log with your report. Flex discovery, connection, full-duplex and slice setup are recorded there.

Hardware smoke checklist

  1. Discovery lists the radio; Test connection succeeds.
  2. On pass start, full duplex is on and two slices are active.
  3. RX and TX Doppler both update during a pass.
  4. FM satellites get the correct uplink CTCSS.
  5. When antenna port mapping is configured, switching U/V ↔ V/U selects the expected RX (and TX) ports in SmartSDR.
