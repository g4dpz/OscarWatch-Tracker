macOS — app or recording blocked on first install

Release builds from GitHub are not code-signed or notarised. macOS may block OscarWatch or bundled native libraries the first time you run them. These steps are usually one-time per install. See the full walkthrough in macOS install (guide by Tim GW4VXE).

  1. Download OscarWatch-osx-arm64 (Apple Silicon) or OscarWatch-osx-x64 (Intel).
  2. Extract with Finder → Open With → Archive Utility.
  3. Run in Terminal: xattr -d com.apple.quarantine /Users/you/Downloads/OscarWatch/OscarWatch (adjust the path).
  4. Launch the OscarWatch executable; use right-click → Open if Finder blocks it.
  5. For each blocked .dylib, use System Settings → Privacy & Security → Allow Anyway and enter your password (often about three libraries).
  6. Grant microphone access when you enable pass recording in Settings → Recording.

Tracking, passes, and radio/rotator control work without pass recording if you skip the PortAudio step.

Pass times look wrong

  • Refresh TLEs (Satellites → Refresh TLEs).
  • Check station latitude and longitude in Settings.
  • Confirm your PC clock and time zone are correct, or enable Use GPS UTC for satellite tracking under Settings → Integrations → GPS when you have a reliable GPS fix. Choose local or UTC for the main window under Settings → Appearance → Times shown in (pass planner has its own control).

No frequencies / wrong mode

  • Select the satellite on the map or pass list.
  • Pick a transponder mode in the frequency panel.
  • Edit or add the satellite in Manage transponder database.

Rotator or radio not connecting

  • Check the serial port in Settings — on Windows, use Device Manager to see which COM port appears when you plug in USB. On Linux, see Linux serial ports if ttyUSB numbers changed after reboot.
  • Ensure radio, rotator, and GPS (if used) each use a different port.
  • Close other applications using the same port.
  • Leave Standby if you expect tracking — Resume for live operation.
  • Settings or the sidebar may show a COM port conflict warning if two devices share one port.

Linux — serial port changed after reboot

  • Do not rely on /dev/ttyUSB0 staying the same — use /dev/serial/by-id/… or a udev alias (for example /dev/USB821H).
  • In Settings, press Refresh, then select or type the stable path and Save.
  • Ensure your user is in the dialout group (sudo usermod -aG dialout $USER, then log in again).
  • Close other programs using the same port (Hamlib, gpsd on that tty, other CAT apps).

Full walkthrough: Linux serial ports.

GPS not connecting or no fix

  • Enable GPS under Settings → Integrations → GPS.
  • Serial: pick the correct port (Device Manager on Windows; stable by-id or udev path on Linux — Linux serial ports), match baud rate (often 4800 or 9600), and use a port not shared with radio or rotator.
  • gpsd: set host and port (default 2947), confirm gpsd is running and reachable on the network (gpsmon host:port on Linux is a quick check).
  • Use Refresh status after saving.
  • Close other applications that might have the GPS port open.
  • Wait for a clear sky view or check the GPS has a valid NMEA output (GGA/RMC).
  • Status bar GPS red = no fix; green = fix active. GPS Time red means time sync is on but GPS UTC is not available yet.
  • Apply fix to station is only available when a fix is active (green GPS).

CAT frequencies not updating

  • Check Pause CAT is off in Settings → Radio.
  • Confirm you are not in Standby mode.
  • Verify rig type and CI-V address (ICOM).
  • For cross-band modes, the radio should be in satellite/split layout (OscarWatch usually sets this at pass start).
  • For receive-only modes (e.g. ISS SSTV with uplink 0), satellite mode should be off — OscarWatch does that on ICOM rigs. Pick the matching band mode (SSTV VHF vs UHF) in the frequency panel.
  • On linear SSB/CW, check Doppler thresholds — very large values can make tracking look sluggish near TCA.

Kenwood TS-2000: no CAT replies / SATL not confirmed

  • The TS-2000 only sends CAT data when the PC asserts RTS. OscarWatch does this automatically — use a straight RS-232 cable or USB adapter that passes RTS through.
  • Match baud 57600 8N1 in Settings and on the radio.
  • Select SAT on the radio and turn memory mode off before tracking — see Kenwood TS-2000 help.
  • Close any front-panel menu; the radio may reply ?; while a menu is open.
  • If SATL is not confirmed, OscarWatch still tracks on FA/FB — check the status bar for a degraded-tracking warning.

Dual radio not connecting (FT-817 / FT-818 / FT-991 / FTX-1 / IC-705 / IC-706 series)

  • Enable Settings → Radio → Dual radio and set a COM port for both downlink and uplink.
  • FT-817, FT-818, FT-991, FT-991A, FTX-1, IC-705, and IC-706 / IC-706MKII / IC-706MKIIG appear only in the dual-radio leg lists — not as single-rig types.
  • Yaesu FT-817/818: match menu #14 baud (suggested 4800; 38400 also works).
  • Yaesu FT-991/991A: match menu 031 CAT RATE (suggested 38400); 8N2 with hardware RTS; use the USB CAT COM port.
  • Yaesu FTX-1: match menu CAT-1 RATE (suggested 38400); 8N2 with hardware RTS; use the Enhanced COM (CAT-1) port, not CAT-2.
  • IC-705: CI-V USB Port = Link to [CI-V]; match baud (default 115200); CI-V address A4 unless changed in the radio menu.
  • IC-706 series: CI-V via REMOTE jack; pick the correct leg type — default addresses 48H (706), 4CH (MKII), 58H (MKIIG); baud 19200; CI-V TRN On.
  • Close Hamlib or other CAT applications using either COM port before starting OscarWatch.
  • After switching from another rig (e.g. IC-910), quit OscarWatch, replug USB, and restart if CI-V or CAT stops responding.

FT-817 / FT-818: downlink stuck, uplink tracks

  • Use Full doppler in the frequency panel (not TX-only or RX-only).
  • On linear SSB, spin the downlink to find the signal, then pause ~1 s so passband trim is captured before doppler resumes.
  • On FM, the dial is locked via CAT during tracking — use Pause CAT in Settings if you need to tune manually.

ICOM: radio stays on Sub or uplink lags after tuning

On IC-910 / IC-9700 / IC-9100 / IC-821H in satellite mode, OscarWatch keeps you on Main for receive while you turn the dial on linear passes. Uplink (Sub) CAT is intentionally delayed for about 2.5 seconds after you stop moving Main so scanning the passband does not select Sub. If uplink seems late right after a long tune, wait a moment — it should catch up. If Sub stays selected with no pass running, press Resume or toggle Standby, or turn satellite mode off and on on the radio. See spinning the dial in Doppler tuning help.

Voice announcements silent

  • Enable voice in Settings → Voice and set trigger elevation.
  • On Linux, install espeak-ng (recommended) or espeak. If neither is present, speech-dispatcher with spd-say is used instead.
  • Use Test announcement in Settings → Voice after installing TTS packages.

Pass recording not working

  • Enable recording in Settings → Recording and press Save.
  • Select an input device — your radio line-in or USB audio interface, not the default microphone unless that is what you use.
  • Press Refresh on the device list if you plugged in hardware after opening Settings.
  • Use Test recording (5 s) to confirm audio levels before a pass.
  • Recording only runs for the focused satellite — click it on the map or pass list first.
  • Check start/stop elevations: the satellite must rise through the start elevation while selected.
  • On Linux, ensure PulseAudio or ALSA is running (libasound2 on Debian/Ubuntu).
  • On macOS, see macOS install if libportaudio.dylib is blocked; grant microphone permission when prompted.
  • Recordings save to %AppData%\OscarWatch\recordings\ unless you chose another folder.

Logs

Help → Open logs folder opens %AppData%\OscarWatch\logs\. Log files help diagnose CAT and rotator errors. API keys are not written to logs.
